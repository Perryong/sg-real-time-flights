# ADSB.fi Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. The user approved implementation; retain native execution from the existing tracker work.

**Goal:** Show actual Changi-area ADSB.fi observations in the existing Cesium viewer.
**Architecture:** Replace the unused provider with a fixed ADSB.fi v3 adapter; reuse the shared poller, normalization, store and stream. Explicit millisecond conversion and provider namespace; no fallback provider.
**Tech Stack:** Existing FastAPI/httpx, React/TypeScript/Cesium.
**Spec:** `docs/superpowers/specs/2026-11-19-live-provider-proposal.md`.

## Global Constraints
- Personal, non-commercial local tracker; visible ADSB.fi link. No provider secrets or archived real aircraft records.
- Fixed 25 NM Changi query, minimum ten-second polling, existing timeout/backoff/401/403 pause.
- Preserve Cesium and all observation-time/unknown-data/demo-isolation semantics.

## Review Focus
- Wrong provider timestamp units must not manufacture fresh positions.
- Existing Airplanes flags must not authorize the new provider.
- Missing/error payloads must not be accepted as healthy empty snapshots.
- Demo attribution must not imply real observations.
- E2E unavailable-state coverage must remain deterministic with the local live feed enabled.
